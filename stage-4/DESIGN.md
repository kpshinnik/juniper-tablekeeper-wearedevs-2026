# Stage 1 implementation invariants

Written before implementation, from the full Stage 1 contract delivered in the fresh room.

* Confirmed occupancy is half-open UTC time. A transaction validates the complete resulting assignment, including unchanged listed reservations, before publishing it.
* Identity, owner, reference and creation timestamp survive amendments. Successful receipts retain the complete original request and response as immutable JSON values; equality distinguishes booleans from numbers and equates exact numerical spellings.
* Authentication precedes receipt lookup. Receipt lookup precedes endpoint validation and resource checks. Failed operations claim no keys.
* Each write works on a private candidate under one lock. Password hashing, cloning, validation, receipt construction and response encoding precede the single state-reference replacement. A socket failure after publication leaves the original receipt retryable. Transport writing cannot cause a second domain mutation.
* Reset and import prepare complete replacement states. Export is an atomic read; nothing depends on another process or a runtime network. Import verifies format, payload integrity and domain structure before replacement. Passwords are salted hashes; existing tokens travel in snapshots.
* JSON parsing, cloning, equality and encoding use explicit stacks, so accepted unknown nested fields remain valid throughout their lifetime. Exact decimal coefficients/exponents avoid floating-point rounding and huge-power construction for comparisons. Unknown fields remain part of request identity even though endpoint validation ignores them.
* HTTP accepts one unambiguous Content-Length, rejects transfer encodings and malformed header syntax, reads the entire declared body before dispatch, and closes after every response. An unread rejected payload can never become a new operation. Deadlines cover header/body reads.

Boundary inputs include absent versus wrong-type fields, empty/maximum-length identifiers and keys, malformed JSON and UTF-8, deep containers, controls and Unicode, exact large/fractional/exponential JSON numbers, numerical-equivalent retries, closed days, adjacent occupancy, nonexistent/repeated local times, true elapsed duration through DST, expired cutoffs, concurrent identical writes, failed multi-moves, and corrupt/repeated replacement snapshots.

Failure behavior is a specified JSON error and unchanged domain state. Transport framing errors close the connection. Valid past bookings are permitted; editability uses the real current clock. Stage 1 contains no browser, combinations, policies, histories, recurring agreements or operator plans.

Implementation is fresh Python standard library code. Every stage is independently buildable. The server requires only bundled Python/IANA timezone data, and runs without filesystem writes or outbound network.

## Independent review repairs

The first review rejected revision `89582510069e984f446060d797e138f4a3bf08f9` despite its green official checks. The original independent reports remain under `reports/stage-1/`; local pre-repair reproductions, source/test hashes and unmodified logs are retained under `checks/evidence/`.

* V-S1-001: an idle socket timeout around buffered reads was not an absolute input deadline. `RequestReader` now uses individual socket receives with a remaining-deadline check on every read, covering headers and body with one deadline.
* V-S1-002: opening/closing wall-clock boundaries are no longer validated as requested booking instants. A gap boundary permits valid early/later grid slots; a booking start still must exist, elapsed duration still uses UTC, and its resulting local end must respect closing. Repeated closing boundaries retain the first-occurrence UTC bound.
* V-S1-003: the reset reservations collection is type-checked before fixture preparation; wrong JSON types produce 400 without replacement.
* V-S1-004: opaque snapshot state now carries exact JSON as a string with its checksum, so ordinary clients can parse and re-encode the envelope without rounding nested numbers. Import still accepts intact older object-payload snapshots. This affects only the implementation-defined snapshot representation, not API number types.
* V-S1-005: a checksum is only transport integrity. Import also validates original receipt fields/timestamps against domain rules and request fields, creation uniqueness, batch shape/reference order/same-restaurant ownership, and mutual occupancy of the recorded batch result. Historical receipts are not compared with current seating assignments; valid receipts remain portable after later amendments or cancellations.
* V-S1-006: instants use exact integer microseconds rather than UTC datetime objects constrained to years 1–9999. Local dates keep their specified range. Gap detection compares IANA fold offsets without a UTC roundtrip. Elapsed-time conversion uses ZoneInfo normally and exact, verified local-offset inversion when only the intermediate UTC date is out of range. Occupancy, sorting, cutoffs, snapshot validation and replay all use the same instant representation; cutoff comparison no longer rounds through floating point. HTTP regressions exercise both valid local calendar extrema plus UTC controls through create, conflict, lookup/list, applicable amendment/cancel, replacement import and original replay.
* V-S1-007: historical IANA offsets can include seconds, which ISO 8601 permits but RFC 3339 does not. New timestamps preserve the exact instant using UTC where representable, or an adjacent minute-aligned offset with compensating clock seconds at calendar extrema. Local starts and restaurant zones remain unchanged. Current reservation responses project legacy timestamp spelling into RFC 3339 without changing stored state; original imported receipt JSON remains immutable, including any historical spelling emitted by an older defective producer. Receipt validation compares the normalized representations, retaining its exact instant/body/order checks. HTTP regressions cover Berlin/New York in 1800 and year 0001 through availability, booking, overlap, cutoff refusal, ordinary-client snapshot replacement, lookup/list and original replay. A separate formatter unit check covers second offsets at both calendar extrema; a constructed legacy-format compatibility fixture is not claimed as a real old-producer execution. Original failing logs and hashes are retained.

The corruption regression was adapted to decode the opaque payload before mutating it; its nonmutation assertion is unchanged. The initial wrong-type reproduction had one cascading assertion after earlier subcases had already replaced state. That original log and test definition are preserved; the permanent regression creates a separate destination per wrong-type subcase so results are independent.
